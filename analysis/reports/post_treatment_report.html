Peloton: effort trend main ride per session, warm-up/cool-down bundled in

Peloton syncs one class as separate warm-up / main / cool-down activities; those are bundled back into a single ride here (grouped by how close together they were recorded), and intensity is judged from the main ride's actual heart rate and power — not the class name — so a hard effort is never miscategorized just because its title doesn't say "HIIT." Filled dots are high-effort main rides (avg HR ≥ 128 or avg power ≥ 150 W); open dots are lower-effort days.

Strength: the first structured program in this dataset's history

A self-directed "Week N Day N" program is the bulk of the sessions below. The "Trainer-led" entries are a different thing: live 1-hour appointments at the trainer's house, logged into Hevy after the fact, so their raw duration is just how long the logging took, not the session — shown here as an estimated 60 min (50 min training + 2×5 min stretch) instead, marked with *. See data/context/life_events.json for the full note on this. Sessions marked 🚴 below were warmed up for with a same-day Peloton ride beforehand — a short ride at home before walking over. For self-directed sessions that's identified by a tight end-to-start gap (logged live); trainer-led sessions are logged well after the fact (shower, eat, then log from a photo of the paper notes), so those are matched by same-day timing instead.

Data gaps & caveats

Worth reading before drawing conclusions — some of these shape the charts above directly.

01
No body weight or composition data anywhere in this repo. The GLP-1/weight-loss context above is entirely user-reported, not queryable. If tracking weight against training load matters going forward, that's a new data source to add, structured the same way data/context/life_events.json is.
02
Ingestion lag: the data behind this page reflects activities processed as of the last build_report_data.py run — . Anything more recent, including up to today, simply hasn't been pulled in yet; that's not evidence of a training pause.
03
Peloton splits one class into multiple synced activities (warm-up / main set / cool-down). Raw activity counts overstate real workout sessions by roughly 3x; the intensity chart above corrects for this by bundling activities recorded close together back into one ride, but the Peloton stat tile does not.
04
Strength sessions carry no set/rep/weight detail — Strava's export for trainer-synced strength activities has no underlying sensor file, so only date and duration exist. Session dates come from activities.csv directly, not the standard per-activity pipeline. Trainer-led sessions' 60-min duration is a manual estimate (user-reported), not logged data — see data/context/life_events.json.
05
Timestamps assume a fixed UTC-5 offset with no DST correction, since the source data carries no per-activity timezone.

Setting the stage

This report stops at description on purpose. Two follow-on passes would turn it into something to plan against:

Comparative — how does this measure up?

  • Benchmark this window's ride cadence/speed/HR against the pre-2020 "long ride" era, not just the flat 2020–2026 injury-era baseline shown here.
  • Track whether outdoor ride distance and duration start recovering toward pre-injury norms now that pain is resolved, or whether Peloton/strength permanently substitute for longer rides.
  • Line up this training ramp-up against the GLP-1 timeline (Mar 2025 onward) once a weight/body-comp data source exists, to see whether increased training coincides with the weight plateau breaking.

Prescriptive — what should change next?

  • Decide which zero-outdoor weeks and gaps in the numbered strength program were deliberate deloads versus just schedule gaps worth closing.
  • Set explicit progressive-overload targets for the strength program now that a real baseline exists to build on.
  • Start logging body weight/composition alongside activity data — the single biggest blind spot for connecting training volume to the stated muscle-mass goal.
  • Define what "success" looks like for the next quarter: ride duration recovery, strength progression, Peloton output trend, or some combination.
